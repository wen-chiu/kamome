# The App Store bundle id is com.chiu.kamome

**Status:** Decided (Chiu, 2026-09-30)
**Supersedes:** spec §11.1 item 5 (the placeholder `com.chiu.kamome.dev`)

## Context
`project.yml` shipped `com.chiu.kamome.dev`, labelled a placeholder "until the
trademark check clears" (spec §11.1). The spec expected the rename to happen
before TestFlight, when it cost nothing. That window passed: an App Store
Connect record and an App Store profile exist for the `.dev` id under team
`6XPGA48GFT` (INFERRED from the Mac's profiles, `handoff-testflight.md`).
Once a version is released on the App Store, its bundle id can never change
(VERIFIED, Apple's rule for a record). The launch review of 2026-09-30 raised
it as #148.

## Decision
Chiu 2026-09-30: *"go for com.chiu.kamome"*. It matches `KamomeLog.subsystem`,
which has been `com.chiu.kamome` all along. Apple does not check the domain;
the only constraint is that the id is free worldwide. Chiu registers it (App
ID, then a new App Store Connect record) before the first upload under it.

## Rejected
- **Keep `com.chiu.kamome.dev`:** it works, but `dev` would be permanent, and
  a separate test build would later need a different id anyway.
- **`io.github.wen-chiu.kamome`:** the one domain Chiu owns, reversed. It is
  the correct form, but longer, and it matches nothing already in the code.

## Consequences
- `PRODUCT_BUNDLE_IDENTIFIER` is `com.chiu.kamome`, and the live doc commands
  follow it. `Docs/demos/phase2` and `phase3_5` record how those gates were
  captured, and keep the old id.
- **A different id is a different app.** TestFlight testers must be re-invited
  under the new record. Their existing trips and films do not carry over: the
  on-device container belongs to the old id, and nothing migrates it.
- The `.dev` record is left in App Store Connect. It can be kept for internal
  builds or removed; that is Chiu's call.
- Simulator installs of the old id stay alongside the new one until deleted.
